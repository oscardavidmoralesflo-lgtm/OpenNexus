# Deploy OpenNexus on Render

[`render.yaml`](../../render.yaml) is a Blueprint for the whole stack:

| Service | Type | What it is |
|---|---|---|
| `opennexus` | web (public) | Caddy gateway: `/api/*` to the API, the rest to the frontend. Health check `/healthz`. |
| `opennexus-api` | private service | FastAPI. Runs `alembic upgrade head` on every start. |
| `opennexus-web` | private service | Next.js dashboard, client portals and widget. |
| `opennexus-whatsapp` | private service | WhatsApp bridge; sessions live in the `whatsmeow` schema of the database. |
| `opennexus-db` | PostgreSQL | No external connections (`ipAllowList: []`). |

Only the gateway is reachable from the internet. Secrets (`SECRET_KEY`,
`ENCRYPTION_KEY`, `WHATSAPP_BRIDGE_TOKEN`, `SETUP_TOKEN`) are generated by
Render in the `opennexus-secrets` group. Never regenerate `ENCRYPTION_KEY`
once data exists: it decrypts the stored AI keys and WhatsApp sessions.

## Deploy

1. Open `https://dashboard.render.com/blueprint/new?repo=<your repository URL>`,
   choose the branch and click **Apply**.
2. When asked for `FRONTEND_URL`, enter the gateway's address, for example
   `https://opennexus.onrender.com` (the name Render gives the `opennexus`
   service), or your own domain once you add it to that service.
3. Wait for the four services to go live.

## Claim it privately

The first visit shows the setup form. It asks for the **setup token**: copy
`SETUP_TOKEN` from the `opennexus-secrets` group. Without it nobody can create
the agency, and once you have, registration closes for good.

## Custom domain

Add the domain to the `opennexus` service under **Settings → Custom Domains**,
then set `FRONTEND_URL` to it and redeploy the API.

## Costs

Every service uses the `starter` plan (always on; the WhatsApp bridge must not
sleep) and the database `basic-256mb`. Change `plan:` in `render.yaml` to scale.
